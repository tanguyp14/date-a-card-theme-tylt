# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

The Shopify theme for **Date A Card (DAC)**, a French TCG (trading card game) shop. It sells single cards, products and accessories, buys back cards ("rachat de cartes"), and handles tournament registrations ("inscription tournoi"). It is based on Shopify's **Refresh** theme v16.1.0, part of the Dawn family. The repo is plain Liquid/CSS/JS with no build step, no package.json, and no test suite. Merchant-facing text and setting labels are in French.

## Commands

Use the Shopify CLI (`shopify`, installed via Homebrew):

```sh
shopify theme dev --store <store>.myshopify.com   # local preview with hot reload
shopify theme check                                # Liquid/JSON linter (the only lint available)
shopify theme pull --only sections/header-group.json  # resync admin-edited JSON back into the repo
shopify theme push --unpublished                   # upload as a new unpublished theme
```

The store domain isn't recorded in the repo. Ask the user for it.

## Sync with the Shopify admin

- The repo is likely connected to the store through Shopify's GitHub integration. Merchant edits made in the theme editor get committed back as JSON changes in `templates/*.json`, `sections/*-group.json` and `config/settings_data.json`. Those commits are often minified single-line JSON. Pull or rebase before editing these files so you don't clobber the merchant's changes, and expect "Resync" commits that re-format them.
- Treat `templates/*.json`, `sections/*-group.json` and `config/settings_data.json` as editor-owned content. Change layout and logic in `.liquid` files and their `{% schema %}`, not by hand-editing content JSON, unless that's the task.
- Don't commit `.DS_Store` changes. The file is tracked, and there is no `.gitignore`.

## Architecture notes (non-obvious parts)

- **Upstream Dawn/Refresh structure.** The structure is unchanged from upstream: `layout/theme.liquid` → `sections/header-group.json` / `footer-group.json` → JSON templates → `sections/*.liquid` → `snippets/*.liquid`. Assets are per-component CSS/JS loaded by each section. JS uses custom elements defined in `assets/global.js` and similar files. When you customize something, keep upstream's naming and idioms so the code still diffs cleanly against Refresh.
- **Custom header "quick links" (secondary menu).** These are added in `sections/header.liquid` through the `show_secondary_menu` and `secondary_menu` schema settings. On desktop they render as red arrow links above the main menu. On mobile, `snippets/header-drawer.liquid` renders them after the main-menu items. Changes to the header menu usually have to touch both files. Shopify allows only one `link_list` setting per section schema (the GitHub sync rejects the file otherwise). That's why the quick-links menu is a `text` setting (`secondary_menu_handle`) resolved with `linklists[...]`.
- **`blocks/ai_gen_block_*.liquid`.** These are theme blocks generated by Shopify's AI block generator. The original French prompt is kept in each `{% doc %}`. Each block scopes its CSS with `block.id` (`ai_gen_id`). They're referenced by ID from template JSON, so don't rename them.
- **Alternate templates.** `product.inscription-tournoi.json` and `product.inscription-menu-dac.json` are for tournament sign-ups. `collection.tournoi(s).json` list tournaments. There are also `page.rachat-de-cartes*.json` and `page.cartes-a-l-unite.json`. The tournament fields come from a private app block (`shopify://apps/tournois-tylt/blocks/tournament-fields/...`, metafield namespace `tournament_fields`) that lives outside this repo. Product pages also include a `schema-breadcrumbs` app block.
- **Metafield definitions.** These are listed in `.shopify/metafields.json`. Custom collection metafields `custom.sous_menu_handle` and `custom.carte_unite_menu` are defined but not currently referenced in theme Liquid.
- **Translations.** Upstream strings are in `locales/` (`t:` keys). Recent customizations hardcode French labels in schemas instead of adding locale keys.
